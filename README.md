# CALR: Guiding Reasoning Models toward Efficient Reasoning with Correctness-Aware Length Rewards

English | [简体中文](README.zh-CN.md)

**CALR** is a length-aware reward designed to make mathematical reasoning more concise while preserving accuracy as much as possible. Built on GRPO, it uses the shortest correct response sampled for each problem as a length reference. Only correct responses receive a bounded penalty for excess length; incorrect responses always receive zero reward. This preserves the reward preference for correct answers while encouraging shorter solutions.

On Qwen3.5-2B, CALR reduces average output length by **6.72%** on MATH500 compared with the original model, with accuracy changing from 70.8% to 70.0%. Compared with correctness-only GRPO, it improves accuracy by 2.0 percentage points and reduces average output length by 10.85%. On AIME24, CALR achieves the same number of correct answers as the original model while using 3.89% fewer output tokens on average.

## Method

### Motivation

Our correctness-only GRPO baseline assigns a reward of 1 to correct responses and 0 to incorrect ones, with no explicit incentive to reduce unnecessary output. Subtracting an unrestricted length penalty from every response can instead make a short incorrect answer more rewarding than a long correct one.

CALR keeps every correct response above every incorrect response in reward. It then differentiates correct responses by their excess length relative to the shortest correct response for the same problem, rather than imposing a fixed target length across all problems.

### Reward

We sample eight responses per problem. If at least one is correct, we use the shortest correct response as the reference, normalize each correct response's excess length, and map it to a bounded penalty:

$$
d_i=\frac{\max(0,L_i-L_{\min}^{+})}{\max(L_{\min}^{+},\tau)},\qquad
R_i=\begin{cases}
1-\alpha\dfrac{d_i}{1+d_i}, & c_i=1,\\
0, & c_i=0.
\end{cases}
$$

| Symbol | Meaning |
|---|---|
| c | Correctness indicator: 1 for a correct answer, 0 otherwise |
| L | Number of output tokens in the response |
| Lmin+ | Length of the shortest correct response in the group |
| d | Normalized excess length relative to the reference |
| α = 0.1 | Upper bound on the length penalty for a correct response |
| τ = 256 | Lower bound on the normalization denominator, preventing very short references from amplifying length differences |

The shortest correct response receives a reward of 1. Other correct responses receive rewards greater than 0.9 and at most 1. Incorrect responses receive 0 regardless of length; if every response is incorrect, all rewards are 0. The reward therefore favors concise correct solutions without favoring an incorrect answer simply because it is shorter.

We retain GRPO's within-group reward normalization. A positive reward does not necessarily imply a positive advantage: a longer correct response can still have a negative advantage.

## Results

All experiments start from the official post-trained Qwen3.5-2B model. Base denotes this model without additional training, not Qwen3.5-2B-Base. GRPO and CALR are trained directly from the original model for 100 optimizer steps on the same 1,600 MATH problems. SFT is a separate QLoRA baseline trained on 1,887 teacher trajectories generated by Qwen3.5-27B; it is not a prerequisite for the RL runs.

## Experimental Setup

| Component | Implementation |
|---|---|
| RL training | GRPO and CALR implemented with TRL, using LoRA and single-GPU BF16 training |
| Hardware | One NVIDIA RTX 6000D GPU with 84GB of memory |
| Response generation | vLLM batch sampling, with up to 16 responses per batch and model weights synchronized from the training process |

## Usage

Run these commands from the project root on a Linux GPU server with Python 3.12. Replace the model path with your local Qwen3.5-2B directory.

### Setup

```bash
uv sync --locked --extra gpu
export MODEL=/path/to/Qwen3.5-2B
```

### Training

```bash
export METHOD=calr  # Set to grpo for the correctness-only baseline
uv run --locked --extra gpu python main.py train --method "$METHOD" --model "$MODEL" \
  --export "runs/${METHOD}_model_copy" --output "runs/$METHOD" --run
```

### Evaluation

```bash
export DATASET=math500  # Set to aime for AIME24

# Original model
uv run --locked --extra gpu python main.py evaluate --method base --model "$MODEL" \
  --dataset "$DATASET" --output "runs/base_$DATASET" --run

# Trained model: use the same METHOD as in training
uv run --locked --extra gpu python main.py evaluate --method "$METHOD" --model "$MODEL" \
  --adapter "runs/$METHOD/final" --dataset "$DATASET" \
  --output "runs/${METHOD}_$DATASET" --run
```

Evaluation includes automatic scoring. New outputs are saved under `runs/`; the reported results are stored under `results/`.
